# 紫微斗数：外部命盘接入与阅读流程

本页为 莉莉丝（Lilith） 原创参考模块，不是本地安星引擎。它接收可追溯的外部紫微盘，核对资料、设置及结构，再提供文化性解释与反思。没有真实计算结果时，不由模型凭记忆安十四主星、编造四化飞线或运限，也不声称“本地排盘已完成”。紫微斗数不是经科学验证的命运、人格或健康检测工具。

## 一、先区分四种请求

**已有盘求解读**：优先读取原盘、导出资料和设置。不要求用户把出生信息重新发送给陌生服务；只要原盘能够确认口径，很多解读可用匿名化资料进行。

**只有出生资料求排盘**：收集必要参数，但当前参考模块不计算命身宫、五行局与安星。没有经过测试的外部或本地引擎就停在待排盘，请用户提供可信盘面，不制作仿真结果。网上工具能排盘也不等于已经在此项目接入或验证。

**问具体年份**：除了本命盘，还需要真实的大限与该年流年资料及其起算口径。仅有本命截图不能推导已验证的当年盘；可以讲一般层次但不偷偷补宫干与四化。

**学习术语**：可直接说明十二宫、十四主星、身宫、三方四正及四化。教学例子与实际用户分开，明确“假设”，不用虚构生日让例子装成真实命中。

## 二、收集信息的层次

### 用户可确认的基本资料

- 出生日期的原始写法及公历或农历；农历务必说明是否闰月。
- 钟表时间或时辰，资料来自出生记录、家人记忆还是自行估计；不确定就给范围，不把整点填成实际记录。
- 出生国家、城市与当年的时区；不需要默认搜集具体家庭门牌。
- 钟表时间是否已经改过夏令时或真太阳时，避免二次校正。
- 采用的排盘规则类别：传统工具若要求男或女，询问用户希望沿用的计算参数，不根据名字、相貌或性别认同猜测。
- 当前讨论主题，以及若看运限，使用的目标日期、年份和年龄口径。
- 已有盘的来源、软件版本、生成时点及设置页，最好保留可匿名化的导出文件。

姓名不是安星必要字段。可以用用户自选代号，不索取证件号、电话、住址或无关亲属私密资料。涉及第三方合盘时，确认对方同意，或改为只讨论用户自己的沟通需要；不得编对方出生日期来凑合盘。

传统性别参数影响部分顺逆规则，它是软件输入而不是价值判断或性格定义。用户不愿选择或采用非二分处理，应让其提供认可的软件盘及规则，或只讲不依赖该参数的知识；不要悄悄替用户选一个默认值。

### 从工具设置获取的资料

本命年界是否按农历正月初一或立春；晚子时归当日还是次日；农历闰月在安命身宫与辅星时怎样处理；时间是否使用民用、地方平太阳或视太阳时；四化表、庙旺亮度表与安星版本；大限顺逆、起限年龄、虚岁或周岁及流年分界；流月与小限有无单独口径。

这些设置最好来自工具导出或文档，不要求普通用户猜门派名称。已有明确口径的盘优先沿用，并写出差异；本模块没有“唯一默认三合盘”可盖过用户的真实来源。

## 四、真实盘面的结构需求

至少有命宫、身宫、十二宫的宫名与地支、宫干、十四主星的落宫、生年四化、五行局，以及来源明确提供的庙旺和辅星。没有辅星或亮度也可以作受限阅读，但应写出缺失而不是填成“无煞”或“全旺”。有些软件在 `majorStars` 里同时存禄存与天马，应按星类过滤，不能把数组长度当十四主星数量。

逐宫可以采用如下字段；空数组只有在来源确实说明该类没有成员时才代表空，否则写缺项状态：

```json
{
  "palace_name": null,
  "branch": null,
  "stem": null,
  "is_body_palace": null,
  "principal_stars": [],
  "auxiliary_stars": [],
  "minor_markers": [],
  "sihua_annotations": [],
  "brightness_annotations": [],
  "data_completeness": null
}
```

每个四化标记需要化禄、化权、化科或化忌的种类，附着星，来源天干，所属本命、大限、流年或宫干层，以及落宫。如果有宫干飞化，再记录出发宫和目标宫；不要只保存“某宫有忌”，丢掉它来自哪一层。身宫用布尔或单独字段标出，不把“身主星”当“身宫主星”。

若看阶段，来源还需给大限年龄范围及宫位、目标年份的流年命宫与十二宫映射、对应宫干和四化。流月或小限必须另有资料与规则；没有这些数据就不做该层具体判断。

## 五、安星之前的时间风险

农历闰月是历法事实；闰月前后半月如何用于安命身宫等是流派或软件规则，二者不能混在一起。已读取的 iztro 文档展示 `isLeapMonth` 与 `fixLeap` 分开的参数，后者的前后半月处理是其软件口径，不是所有紫微流派共同的天文规定。接入其他软件时用其原规则，不套用 iztro 参数名就宣称已一致。

换日与年界也要分开。晚子时归次日可能改变农历日与主星位置；正月初一或立春作为年界可能影响年干及四化。流年使用的年界与本命年界还可能分别配置。用户出现在边界附近时，记录两种候选资料与区别，不凭性格描述挑一张“最像”的盘。

时间校正有民用时、地方平太阳时和视太阳时之别，真太阳时不是只按经度固定增减。需要真实坐标、历史时区、夏令时与日期相关的均时差，并由外部计算工具给结果。此模块可识别可能跨时辰或换日，但没有工具时不报自编校正分钟，也不宣称真太阳时版本更科学地预测命运。

海外出生及历史出生时刻需核实当年时区。遇到夏令时导致的重复或不存在钟表时间，记录来源怎么处理。时间只有范围时，不补一个虚构的准确分钟；若范围跨时辰，请外部来源生成候选盘，最后只讲稳定共同部分。无法确定时辰时，不从生活故事反推一个肯定出生时间。

## 六、结构自查与核对状态

十二宫宫名完整且各一次，十二地支完整且各一次；主星为紫微、天机、太阳、武曲、天同、廉贞、天府、太阴、贪狼、巨门、天相、天梁、七杀、破军，每颗应在本命主星层出现一次。双星同宫可以出现，空宫也正常，不能为“每宫都必须有星”补造主星。

核对命宫与身宫标记和截图一致；在本页采用的常见规则中身宫只寄于命、夫妻、财帛、迁移、官禄、福德六宫之一，但这是识别异常的条件，不是由模型反排身宫。若来源确有特殊规则，要求其说明而非无依据改宫。

四化必须附着于表中真实存在的主星或辅星，文昌文曲左右也可能化科或化忌，不能用“不是十四主星”就删除。一个层通常由其天干产生四项，跨层同星不同化可以并存；不把它误认为本命有多颗同名星。核对大限范围没有莫名重叠、年龄口径一致，来源的流年映射没有与本命宫名混用。

核对截图与导出一致不等于独立重算安星。报告应明确“已核对源盘结构，未本地重算”。只有真实运行过经验证的第二引擎才谈计算交叉核对；两张盘若设置不同，先归因输入与口径差异，不挑符合期望的一张。

## 七、固定阅读顺序

1. 列盘来源、版本、采用口径、完整度与输入误差。
2. 说明只读本命，还是有真实的大限及流年层；先分开各层宫名和标记。
3. 读命宫与身宫，说明主要星曜的文化主题，不把用户定成单一人格。
4. 将命宫放回财帛、官禄、迁移的三方四正，比较资源、行动与外部条件。
5. 定位用户主题宫，读其本宫，再检查三合两宫和对宫；空宫单列借对宫的取法与限制。
6. 检查来源给出的辅星、亮度与生年四化，避免只凭一颗主星或煞星断整个人生。
7. 有经过核实的运限时才按本命、大限、流年顺序叠看，不从流年标签直接断日期。
8. 给可核实的问题、开放情景、现实支持及低风险动作，列仍然未知的资料。

每一步的结果必须能指向来源中具体宫位与星曜。用户问题仅需某一主题时可以压缩篇幅，但不要跳过源盘验证和运限分层。无法确定宫干或四化表时，保留星曜层的受限解释，不为输出完整而临时背表补造。

## 八、合格输出与停止条件

报告头部写“外部盘面文化解读，非本地排盘”，下方列资料采用范围与未验证项。正文把盘面事实、传统主题、用户背景和解释分开；本命主题不表述为“你天生注定”，年份主题不表述为“这个月必定结婚发财”。结束给一至三项可拒绝的反思动作，如比较工作需要、整理沟通期待或建立实际记录。

出生时区、日期、时辰等关键输入不能核实，或现成盘缺完整十二宫与主要设置时，停止具体安星与应期。医学症状、即时安全、法律与财务问题转向合格现实渠道；不能说有化科就不必就医、有化禄就可以买资产。有煞或忌也不得宣称会短命、克亲、必离婚或子女有病。
