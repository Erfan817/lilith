## 早子时与夜子时

子时横跨两天（23:00-01:00），在命理学中有"早子时"和"夜子时"之分：

- **早子时**（00:00 - 01:00）：归属当日，使用当日日柱
- **夜子时**（23:00 - 24:00）：归属次日，使用次日日柱

注：本项目生产 `getEightChar` 设 `sect=1`，是明确的 23:00 换日约定，不代表争议已消失。当地民用钟标 23:00 起使用次日日干排日、时柱，00:00 起沿用该日；恰好 23:00 属于新日。默认固定 UTC+08:00，其他当地民用时区须显式确认 `--timezone`；真太阳时也须显式选择，不能因出生地自行校正。年、月柱与起运仍按出生绝对瞬间比较北京时间交节。

## 时辰判断提示：先追问，不靠生活场景定时辰

不能把日出或用餐习惯当作钟点。季节、纬度、天气、时区、作息都能改变天亮、早餐或睡前对应的实际时间；别称是助记，不是出生时刻证据。

| 用户描述 | 追问与处理 |
|---------|-----------|
| 天刚亮 / 早上 | 追问出生地、季节和大致钟点；不能直接确定卯时 |
| 吃早饭 / 上午 | 追问当时早餐时间与记录依据；不能直接确定辰时 |
| 天还没亮 / 半夜 / 深夜 | 追问具体日期、是否跨午夜及钟点；不能直接确定子丑寅 |
| 天快黑 / 傍晚 / 吃晚饭 | 追问当地钟点与作息；不能直接确定酉戌 |
| 中午 / 下午 / 睡前 | 同样先确认钟点或时辰边界，不从习惯补出时间 |

### 确认后的 range 与 CLI 边界

1. 先复述候选钟点范围（range）及其依据，待用户**确认**后才按该范围讨论；未经确认只能标未知，不能用中点冒充出生钟点。
2. 当前 CLI **不支持任意时间范围**参数。只确认完整传统时辰时可用 `--shichen`，引擎处理该两小时域；子时保留 00:00–01:00 与 23:00–24:00 两段，不能擅选一段。
3. 如果确认的是任意跨时辰范围，可先不传 `--hour` / `--shichen`，保留未知；或把用户分别已确认的方案逐个计算，明确它们只是情景对比。不得声称 CLI 已把任意 range 合并精确计算，不得用两个端点声称穷尽区间。
4. 已确认准确钟点才用 `--hour HH:MM`。钟点与时辰参数互斥；仅有时辰而无明确钟点，`dayun=null`，不能生成精确起运。
