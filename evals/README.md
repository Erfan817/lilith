# 触发与解读评测

这里保存合成中文 prompt 与可验证断言。`python scripts/check_evals.py` 只检查条目、正负案例、字段与断言完整性，**不执行模型，不证明自动加载成功**。

## 两种不同验收

1. **元数据路由**：新旧 description 各进入同一模型的干净上下文，只提供目录摘要和用户消息；记录是否选择本技能、体系及原因。包含明确请求、隐含请求、普通疲惫、科学天文学、排除占卜的医疗/金融请求。模型通过此测试不代表 Claude/Cursor/Hermes 的真实目录发现、权限或加载过程也通过。
2. **解读行为**：新旧技能各进入干净上下文，使用同一合成问题和同一真实程序结果，保留模型原文/工具记录。逐条检查引用实际牌位、未知时刻、无读心、反例与报错处理等。解释体验可人工比较，不能拿词命中当作质量结论，也不能用本代理自己写的答案冒充模型执行。

## 运行纪律

- 每条或每批实验显式记模型、执行时间、版本、输入来源；不保存真实用户信息或密钥。
- 旧版从 git 固定 commit 导出到仓库外工作区，不能在仓库内放第二个 `SKILL.md`。
- 首轮建议用塔罗安全文本、星盘未知时刻、奇门缺引擎三个行为案例。程序结果必须实际运行；LLM解释仍是象征层。
- 可复现输出存在仓库外 `private/` 或独立工作区；公开只发布合成摘要和断言证据。
- 改 description 后须在实际宿主新会话验证目录可发现与自然语言加载，最好分别在 Claude Code、Hermes、Cursor 测试。没运行的宿主写“未验证”，不能宣称跨平台触发率100%。
- `allowed-tools` 只在实现支持的宿主与规则匹配时减少批准；不是评测替身，也不绕过组织权限。

## 真实宿主多轮流程（v0.2.1）

[Hermes完整流程证据](results/host-v0.2.1/summary.json)保存2个真实会话、10轮合成输入与工具事件：无强制预加载的自然语言发现、缺资料追问、未知时刻降级、钟点补充与更正、真实计算文件、默认分享报告。Linux文件和最终盘面经独立CLI重算核对；权限为manual/单轮deny，记录了真实拦截，没有跳过审批。

流程通过不等于解读全部正确：首轮错建议时辰可补大运，已加强入口规则；星盘解释仍出现未经实际搜索的换座时长估计。所有失败与原响应保留，解读质量验收未通过。Claude/Cursor及人工点击权限仍未验证。

## 结果记录

已执行的开发快照见[结果汇总](results/summary.json)，包含实际模型原文和新旧description路由：同一模型在选定案例里两者均通过，不宣称触发率提升。解读使用预先真实计算结果，不是完整宿主工具调用测试；快照SKILL哈希与最终发布文档可能不同。

记录每条 `id/prompt/expected_trigger/model_decision/actual_output/assertion_results/evidence`。程序汇总数量、通过率；未执行的项目标 `not_run`，失败不得改 expected 值凑绿。知识与参考来源的离线完整性属于结构测试，不等于解读质量。
